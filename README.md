## 1. 何ができるアプリか

```text
目標とペースを決める  →  5分タイマーを回す  →  サイクルを続けるとアバターが進化する
                                            →  止まると色が抜けていく
```

| 画面 | 何をするか | ファイル |
| --- | --- | --- |
| **トップ** | たまごが出迎える。ここから始める | `src/pages/TopPage.tsx` |
| **目標ポップアップ内の一覧** | 持っている目標を並べて、育てるものを選ぶ | `src/pages/GoalsList.tsx` |
| **目標設定** | 目標・期限・ペース（n日に1回）・アバターの色と名前を決める。**新しい目標を作る画面**なので、入口は目標一覧とダッシュボードのボタンだけ（メニューには無い） | `src/pages/SetupPage.tsx` |
| **ダッシュボード** | アバター・進化ゲージ・5分タイマー・カレンダー | `src/pages/MainPage.tsx` |

ログイン時は、チュートリアル未完了なら **トップ → 目標設定 → ダッシュボード**、
完了済みで現在の目標がなければ **目標設定 → ダッシュボード**、
現在の目標があれば **ダッシュボード**を表示します。
「はじめる」「スキップ」で完了をアカウントに保存します。過去に目標を作ったアカウントも完了済みとして扱います。
ログイン中の `user_id` に一致する目標を読み込み、最後に選んだ目標を表示します。
選択履歴がない場合や、その目標が削除されている場合は最新の目標を表示します。
選択履歴はアカウントごとにこのブラウザ内へ保存し、目標一覧から切り替えられます。
期限切れでも継続中として扱います。新しい目標を作っても、以前の目標と記録は残します。

ダッシュボードでできること:

- **5分タイマー** — ▶ を押すと開始。5分たったら「記録する」で今日の達成を保存する。記録後も計測は続けられる
- **当日の計測時間を保存** — 開き直しても、別の端末からでも同じ目標の時間を復元する。計測中に閉じた時間は加算し、一時停止中は加算しない。目標切り替え時は元の計測を停止して保存する。日本時間の午前0時で区切り、新しい日は0秒・停止中から始める
- **記録だけつける** — タイマーを回さずに今日を達成にする（達成済みの日は出ない）
- **カレンダー** — 週表示と月表示。達成率と連続サイクル数もここで集計している
- **新しい目標をはじめる** — もう1本増やす。いまの目標は目標一覧に残る
- 期限の延長 / 最初から
- 期限が切れると「期限を1ヶ月伸ばす」か「目標一覧を見る」を出す（ここからは新しい目標を作らない）

## 2. ゲームのルール

**原則: 記録から計算できるものは保存しない。** 連続サイクル数も気分もステージも、
`records`（達成した日）と `cycle_days` / `started_at` から**毎回その場で計算**します。
DB に置く導出値はありません（唯一の例外は「進化の演出をどこまで見せたか」）。

### サイクル — すべての判定の単位

目標ごとに「**n日に1回**」を決め、連続もお休みも「日」ではなく**サイクル**で数えます。
頻度がそのまま難易度設定になるので、週1回の人が毎日しょんぼりすることがありません。

| 設定 | サイクル長 | 「連続」の意味 |
| --- | --- | --- |
| 毎日 | 1日 | 毎日つける |
| 2日に1回 | 2日 | 2日に1回つける |
| 3日に1回 | 3日 | 3日に1回つける |
| 週に1回 | 7日 | 週に1回つける |

- 起点は**目標を作った日**（`goals.started_at`）。`cycleIndex(d) = floor((d − started_at) / cycle_days)`
- 1サイクルに何回つけても**1サイクル達成**
- 進行中のサイクルも、つけた時点で連続に数える
- **ペースはあとから変えられません。** 変えたいときは新しい目標＝たまごから
- 目標は**同時に何本でも持てます**。アバターも記録も目標ごとに別々で、
  どれを育てるかは**目標一覧**で選びます。切り替えても前の目標と記録は消えません

### 進化（ステージ 0〜3）— どこまで育ったか。下がらない

原典は `src/avatar/stage.ts` の `STAGES`。**判定は起点サイクルから1サイクルずつ走査し、
その時点の「次の条件」だけを見ます**（いまの値で当てはまる最大のステージを採ると、
卵から成体へ飛んでしまうため）。

| ステージ | 到達条件 | 増えるもの |
| --- | --- | --- |
| 0 たまご | 初期状態 | 殻のまま。気分を持たない |
| 1 幼体 | 2サイクル連続 | からだ・あし・くちばし・小さいとさか |
| 2 成体 | 直近5サイクルのうち4サイクル | つばさ ＋ 一回り大きく ＋ とさかが立派に |
| 3 完全体 | 14サイクル連続 | マフラー ＋ 冠 |

> **完全体はいま OFF です**（成体が最終ステージ）。`src/avatar/stage.ts` の `FINAL_FORM` を `true` にすれば戻ります。

- 一度上がったステージは**下がりません**
- 進捗は「あと○」ではなく `x / y`（ステージ2は窓の条件なので「あと○回」が嘘になる）
- 演出は条件を満たした瞬間に1回だけ。`avatars.seen_stage` で管理します

### 気分 — 今の調子。上下する

原典は `src/state/logic.ts` の `MOODS`。今のサイクルを `c`、記録があるいちばん新しい
サイクルを `last` として、`idle = c − last`、`run` = `last` を末尾とする連続達成サイクル数
（ただし `idle >= 2` なら 0）で決まります。**`idle == 1` でも連続が残るので、
1サイクルぶんの猶予は定義から自然に出ます。**

| 気分 | 条件（上から順に見る） | 彩度 / 明度 | 見た目 |
| --- | --- | --- | --- |
| ~~しずみこみ~~ | 停止中（`SINK_MOOD`） | 4 / 58 | 伏せて動かない・どんより |
| ぐったり | `idle >= 3` | 8 / 58 | うずくまってうなだれる・どんより・叩いても反応しない |
| うつむき | `idle == 2` | 40 / 80 | 歩かず、休憩と叩かれた反応だけ |
| すこし元気 | `run == 1` | 56 / 80 | 歩き回る・跳ばない |
| 元気 | `run == 2` | 56 / 80 | 歩き回る・跳ぶ |
| いきいき | `run` 3〜6 | 56 / 80 | 歩き回る・にっこり・光の粒 |
| かがやき | `run >= 7` | 56 / 80 | 後光で輝く・にっこり・光の粒 |

- **色が変わるのは落ち込んだときだけ。** すこし元気〜かがやきは、いきいきの色のまま
  （色選択画面の見本と同じ）。うつむきは彩度だけ少し落とし、ぐったりは彩度で沈めます
- **明度は 58 より下げません。** 暗く沈めると汚く見えるうえ、
  前かがみの姿勢とどんよりのエフェクトで十分しんどそうに見えるため
- **しずみこみ（4サイクル放置）はいま止めています。** 3サイクル以上の放置はすべてぐったり。
  定義は `SINK_MOOD` に残してあり、`MOODS` の先頭に入れ直せば戻ります
- **色相はユーザーが選んだ色に固定。** 色相まで動かすと、選んだ色が画面から消えます
- 気分はステージ1以上のもの。たまごに気分はありません

> なぜ活力（0〜100 の保存値）をやめたか: 計算できる値を保存していたので、
> 読み込みのタイミングでズレました。記録だけを保存すれば、いつどこで開いても同じ絵になります。

データの流れは [ARCHITECTURE 3章](./ARCHITECTURE.md#3-データの流れ)に図があります。

## 3. 動かす

### 初回だけ

**Node.js v22** を使用します。Vercelのビルドも22.xに揃えています。

```bash
node -v && npm -v          # command not found なら nodejs.org の LTS を入れる

git clone https://github.com/kuramochi703/keep-motivation-app.git
cd keep-motivation-app
npm install                # 数分かかることがある
cp .env.example .env       # ← 中身を埋める（下記）
```

| 環境変数 | 中身 |
| --- | --- |
| `VITE_SUPABASE_URL` | Supabase プロジェクトの URL |
| `VITE_SUPABASE_ANON_KEY` | Supabase の anon key |

> **鍵は Git に入れません。** `.env` は `.gitignore` 済み。共有はチャットの DM などで。

> **DB を新しいプロジェクトへ移しました。** テーブルの定義は
> [`supabase/schema.sql`](./supabase/schema.sql) が原典です。新しい Supabase
> プロジェクトを作ったら、SQL Editor にこのファイルを貼って1回実行し、続いて
> [`supabase/timer_status.sql`](./supabase/timer_status.sql)、
> [`supabase/goal_commands.sql`](./supabase/goal_commands.sql) の順に実行してください。
> その後、
> `.env` の2つの値を新しいプロジェクトのものへ差し替えてください
> （**旧プロジェクトは消しません。** しばらく様子を見てから休止します）。

### 毎回

```bash
npm run dev                # → http://localhost:5173/
```

保存した瞬間にブラウザへ反映されます（HMR）。止めるのは `Ctrl + C`。

### デバッグ画面

`npm run dev` 中に **http://localhost:5173/debugPage** を開くと出ます
（本番のビルドには入りません）。

いま何が起きているか（気分・ステージ・連続サイクル数・DBの生の値）を一覧できるほか、
**日付を動かして、記録をつけたり消したりできます**。

| したいこと | 使うもの |
| --- | --- |
| 14サイクル連続を作って完全体を見る（`FINAL_FORM` が ON のとき） | 「日付」の `+1日` と「記録」の `達成にする` を交互に |
| 3サイクル放置の「ぐったり」を見る | 記録を1つつけてから、日付を3サイクルぶん進める |
| 進化の演出をもう一度見る | 「進化の演出」で見せ済みを戻し、ダッシュボードを開く |
| 試した記録を片付ける | 「記録」の `消す` / `記録を全部消す` |
| たまった目標を見る・消す | 「目標」の一覧（**ここにしかありません**） |

> **ここでの削除はDBから本当に消えます。取り消せません。** 本番の画面には削除がなく、
> 記録も目標も増えるだけなので、行が消えるのはこの画面だけです。仕組みは
> [ARCHITECTURE 4章](./ARCHITECTURE.md#デバッグ画面開発時だけ)。

### アカウントを作成・ログインする

開くとログイン画面が出ます。**「Googleでログイン」**、またはメールアドレスとパスワードでログインできます。

- **初めての方は「アカウントを新規作成」**を押し、メールアドレス、8文字以上のパスワード、
  確認用パスワードを入力してください。登録後は初回案内へ進みます。
  メール確認が有効な環境では、届いたメール内のリンクを開いてからログインしてください。
- **Googleで初めてログインする場合も、同じボタンでアカウントを作成できます。**
  登録済みの方は、同じメールアドレスのGoogleアカウントを選んでください。
  同一メールのアカウント連携は [Supabase Auth](https://supabase.com/docs/guides/auth/auth-identity-linking) が行います。
- メールアドレスには**本人が受信できるアドレス**を使ってください。
- **一度入れば、リロードしてもログインは続きます**（セッションはブラウザに残ります）。
  終わるときは画面右上の「ログアウト」
- 目標も記録も**自分のものしか見えません**。DB 側の RLS が他人の行を返さないようにしています

| 症状 | 対処 |
| --- | --- |
| 「メールアドレスかパスワードが違います」 | 登録時のメールアドレスとパスワードを確認 |
| 「現在、新規登録を受け付けていません」 | 管理者が Supabase の Authentication 設定で Email と Allow new users to sign up を有効にする |
| 確認メールが届かない | 迷惑メールを確認。送信上限の場合は時間をおいて再試行 |
| Googleログインを完了できない | 下記のGoogleプロバイダ設定・戻り先URLを確認。Google側がテスト公開ならテストユーザーの追加も確認 |
| ログイン画面が出ずに読み込み中のまま | `.env` の URL / anon key が合っているか |

新しい Supabase プロジェクトでは Email と新規登録を有効にしてください。
メール確認を使う場合は、Auth の URL Configuration の Site URL をアプリの URL に設定してください。

Googleログインを別のSupabaseプロジェクトで使う場合は、[公式の設定手順](https://supabase.com/docs/guides/auth/social-login/auth-google)に沿って設定してください。

1. Google Auth PlatformでOAuthクライアント（ウェブアプリケーション）を作成します。
   承認済みJavaScript生成元にアプリのオリジン、承認済みリダイレクトURIに
   `https://<SupabaseプロジェクトID>.supabase.co/auth/v1/callback` を登録します。
2. SupabaseのAuthentication → Sign In / Providers → Googleを有効にして、Client IDとClient Secretを設定します。
   **Client SecretはSupabase側だけに保存し、`VITE_`環境変数やコードに入れないでください。**
3. SupabaseのURL ConfigurationでSite URLを設定し、Redirect URLsに開発用の
   `http://localhost:5173/` と、本番アプリの戻り先URLを登録します。
   `127.0.0.1` や別ポート、サブパスを使う場合は、そのURLも追加してください。
4. 既存ユーザーと新規ユーザーでGoogleログインし、既存の目標・記録が表示されることを確認します。

アプリは現在のオリジンとパスを戻り先に指定します。戻り先URLからのセッション取得はSupabase SDKに任せています。
Googleログインのためにフロントエンドへ追加する環境変数や、DBスキーマの変更はありません。

| コマンド | 何をするか | いつ使うか |
| --- | --- | --- |
| `npm install` | ライブラリを入れる | 初回 / `package.json` が変わった時 |
| `npm run dev` | 開発サーバー起動 | 開発中ずっと |
| `npm run build` | 型チェック＋本番用に書き出し | **push する前に必ず**（[TEAM 5章](./TEAM.md#5-git-の運用ルール)） |
| `npm run preview` | `build` の結果を確認 | 本番の見た目を確かめたい時 |
| `npm test` | ルール・認証・ログイン後の遷移・目標読み込みのテスト（DBはモック） | ルールや状態管理を触った時 |

## 5. 困ったとき

| 症状 | 対処 |
| --- | --- |
| `npm: command not found` | Node.js が未インストール |
| `Cannot find module 'react'` | `npm install` のし忘れ |
| ポート 5173 が使用中 | 別のターミナルで起動中。`Ctrl+C` か `npm run dev -- --port 5174` |
| 画面が真っ白 | `F12` → Console タブの赤いエラーを読む |
| データが読めない / 保存されない | `.env` の2つの値が正しいか。Console に `Supabase読み込みエラー` が出ていないか |
| アバターが出ない（枠だけ） | WebGL が使えない環境。Console に `[avatar]` で始まる警告が出る |
| どうにもならない | `rm -rf node_modules package-lock.json && npm install` |

**WSL / Windows の人へ**: WSL 内で `npm run dev` しても、通常は Windows 側のブラウザから
`http://localhost:5173/` で開けます。開けない場合は `npm run dev -- --host` で起動し、
表示された Network アドレスを使ってください。

**15分考えてわからなかったら、人に聞く**のがチームのルールです（[TEAM 7章](./TEAM.md#7-詰まったときのルール)）。
